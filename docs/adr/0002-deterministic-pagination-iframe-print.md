# ADR-0002：打印导出采用「确定性分页 + 隐藏 iframe 打印」

日期：2026-10-10 · 状态：已采纳

## 背景

导出是产品的第一优先级：A4/B5/A5 等尺寸的 PDF/图片，排版美观、可直接打印装订。
候选方案：

1. 浏览器打印（依赖 @media print 与分页 CSS）；
2. @react-pdf/renderer / jsPDF 直接生成矢量 PDF；
3. 隐藏 iframe：克隆页面 DOM + 动态 `@page` + `print()`。

## 决策

主通道采用方案 3，辅以自研确定性分页：

- 内容先经过**测量引擎**（离屏渲染、同构组件、字体就绪后测量）得到块高度；
- 纯函数 `paginate()` 把块/单元装箱到固定尺寸的页面与分栏；
- 预览、打印、PNG 三处渲染**同一批 DOM**，保证所见即所得；
- 打印时把页面节点克隆进隐藏 iframe，复制样式表，注入字面 mm 的 `@page { size; margin: 0 }`，
  调用 `contentWindow.print()`。

## 理由（调研结论）

- Chrome「另存为 PDF」输出**矢量文字**并自动嵌入字体子集，中文无需打包 10–20MB TTF；
- 方案 2 需要随包 CJK 字体（体积灾难）且要重实现分页；
- 方案 1 的 `@media print` 与整个应用样式耦合，难以保证像素级一致，且无法支持 PNG 复用；
- Chromium 不支持 `@page` margin box 与 `marks/bleed`，页码/页眉必须在 React 中绘制（已如此实现）。

## 影响

- 排版单位使用 mm（打印精确）与 em（随字号缩放）；测量层与渲染层必须同构（有注释约束）；
- 额外提供「一键图片型 PDF」（html-to-image → jsPDF）与 PNG（≤384DPI）通道满足分享场景；
- 打印对话框须提示：边距=None、缩放=100%、背景图形=开（已内置 UI 提示）。
