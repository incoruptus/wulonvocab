# ADR-0003：Schema 驱动的动态字段（而非固定词条结构）

日期：2026-10-10 · 状态：已采纳

## 背景

需求的核心是「动态字段管理」：用户可自定义词条板块（词性下分释义与用法、词族、词性变换、
联想、例句、情景标签……并允许任意添加）。同时要满足「导入 JSON 即自动排版」。

## 决策

1. 词条 = `headword + values(sectionKey → value)`；字段清单由 `Schema.sections` 描述；
2. 每种字段类型（14 种）有**唯一规范值形态**与 `normalize()`；
3. UI（编辑器/预览/导出）全部按 Schema 动态生成，无任何硬编码字段；
4. 导入时：文档自带 Schema > 使用目标词库 Schema > 从数据**推断** Schema；
5. Schema 之外的键永不丢弃（进入「未定义字段」，可提升/删除）；字段改名迁移数据。

## 备选与取舍

- **固定字段（如 Anki 固定 Front/Back）**：简单但无法满足自定义板块需求；
- **自由 JSON blob + 模板语言**：灵活但编辑体验与导出排版不可控；
- 采纳折中：**类型化字段注册表**——新增类型只改一处注册表 + 两个 switch + 一份文档，
  换来全程类型安全与统一的容错归一化。

## 影响

- `sections.ts` 是领域核心，任何 normalize 改动必须补单测（已有覆盖）；
- 分页引擎按字段类型决定可拆分性（`SPLITTABLE_TYPES`），语义与渲染保持同步；
- Skill（AI 词表生成）可以直接引用同一套字段规范，形成闭环。
