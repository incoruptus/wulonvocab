## 2. D1 秩序：管理排序与学习顺序（反馈 1「多样化」）

### 现状【事实】

- 列表排序只有三项：`order / az / recent`（`EntryList.tsx:156-158`，实现 `:76-78`）；排序与筛选都是组件局部 `useState`（`:47-51`），**刷新即重置，不入 store、不同步**。列表**未虚拟化**（`filtered.map` 全量渲染，`:204-228`），大词库分区需实测帧率。
- 导出侧另有 `ExportSettings.sortMode: "list" | "az"`（`types.ts:348-349`），与列表排序是两套。
- 学习队列：`StudyConfig.queueOrder: "due" | "shuffle"`（`study/types.ts:49`）。复习按 `srs.due` 升序（`queue.ts:72-77`）；**新词永远按数组原序引入**（`queue.ts:80-82`），没有任何顺序选项。这是「想按字母/乱序/倒序学新词」落空的根因。
- `Entry` **没有 `order` 字段**（`types.ts:240-254`）；「词库顺序」＝数组顺序。（`SectionField.order` 是字段排序，与词条无关）

### 证据

- R3 §3.1：Anki 浏览器多列排序（Sort Field / Due / Interval / Ease / Lapses / Created）＋新卡 gather/order 与复习 order 分离；Mochi Views 排序（字母/最新/最近复习/随机）；墨墨按熟知度。**字母序在业界是管理视图，不是学习顺序。**
- R2 §4.1：字母序无学习收益，且聚集形近词（adapt/adopt/adept）＋序列位置效应；例外是拼写训练可按韵脚/词族。
- R1 §5.1/5.2：选顺序是安全自由；长期「简单优先/固定顺序」会破坏间隔效应。

### 方案【建议】

1. **管理排序（EntryList）改两段式**：维度 × 方向。维度集合：词库顺序、字母、最近添加（`createdAt`）、最近编辑（`updatedAt`）、到期时间（`srs.due`）、记忆强度（`srs.stability`）、遗忘次数（`srs.lapses`）、乱序。方向：正/倒（乱序无方向）。默认仍是「词库顺序 · 正」。
2. **学习顺序独立配置**：`StudyConfig.newOrder: "list" | "listDesc" | "az" | "azDesc" | "shuffle"`（缺省 `list`，向后兼容）；复习排序 `reviewOrder: "due" | "retrievability"`（缺省 `due`；`retrievability`＝R 升序，最可能忘的优先，R2 建议 #12）。`queueOrder` 保留为整队打散开关，语义不变。
3. **乱序只存 seed，不存结果**：一次会话/一次视图固定，避免每次渲染都跳（R3 §3.1）。
4. **持久化分域**：管理排序/筛选/分区/保存视图＝**本地视图偏好**（按 bookId 存 IndexedDB，不同步，与外观设置同口径）；`newOrder / reviewOrder / batchSize`＝**StudyConfig，随同步**（`setStudyConfig` 立即上云）。
5. **「词库顺序」定义需明确**：当前＝数组顺序。若要支持手动拖动重排，需新增 `Entry.order`（导入按文件序赋值）并进同步材料哈希；**本轮建议先不做拖动**，只把「数组顺序」正/倒开放，成本最低且不动数据模型。
6. 按 S/due/lapses 排序的维度在 UI 标注「会随学习变化」，避免用户以为列表乱跳是 bug（R3 冲突点）。
7. 导出排序与列表排序**保持两套**，但在导出面板显示「当前列表排序：X」并提供「沿用列表排序」一键，消除困惑（不合并语义，避免影响既有导出模板）。

### 验收

- 新词引入顺序在五种 `newOrder` 下与预期一致（纯函数单测，注入 rng/now）。
- 刷新页面后排序/筛选/分区保持；换设备后管理排序不跟随（本地），`newOrder` 跟随（同步）。
- 复习队列在 `retrievability` 模式下按 R 升序，且相似避让与回炉插入位仍生效。

### 风险与人日

- 风险：大词库全量排序卡顿（几万词）→ 内存一次排序 + 缓存，必要时 Worker；`Entry.order` 若后置引入需迁移。
- 人日：**2–3**（不含拖动重排）。

## 3. D2 分区与学习批次（反馈 2「分组依据」）

### 现状【事实】

- 只有筛选，没有分组：状态四档 + 星标 + **单个**标签下拉 + 搜索（`EntryList.tsx:62-79, 117-169`）；grep 无 `groupBy`/分区渲染/折叠分区。
- 两套标签相互独立：`Entry.tags`（词条级，`types.ts:243-244`）与 schema 字段「情景标签」`contexts`（`presets.ts:101`、`sections.ts:831`）。
- 词库级 `Wordbook.tags`（`types.ts:270`）只用于词库列表。

### 证据（这是本轮证据最硬的一块）

- **语义集组有害初学**：Nation 2000 明确警告；Waring 1997 重复验证；Erten & Tekin 2008 语义集组不如语义无关组。【事实，强】
- **主题聚类优于语义聚类**：Tinkham 1997（餐厅场景但词分属不同语义类）。【事实，中–强】
- **词汇材料块状优于交错**：Brunmair & Richter 2019 元分析，词汇 g = −0.39（负号＝块状更好），与绘画/数学相反。【事实，强】
- **形近对比有收益但有条件**：Baxter 2021 只在阅读能力较强儿童显著，且学习期正确率更低 → 放到复习辨析，不放初学。
- R3 §3.2：Mochi Views 是「保存的镜头」，**不复制卡片**；复制会带走 FSRS 状态造成同词两份调度。

### 方案【建议】：两个概念分离

**A. 分区（浏览/导航，任意维度）**

- 「分组依据」下拉：词条标签、情景标签、首字母、学习状态、词性（若 schema 有）、记忆强度桶（S <1d / 1–7d / 7–30d / 30–180d / >180d）、来源（`Entry.source.kind`）、不分组。
- 呈现：可折叠分区 + 每区计数 + 「未标记」兜底区；首字母按 A–Z 归一化（大小写/重音），非字母归「#」。
- 多标签词条可同时出现在多个分区（标签是多对多，首字母是单值，**不共用一套「唯一分组」模型**）；提供「按首个标签」与「全部标签」两种归属口径，默认首个。
- 保存视图：当前「分组 + 筛选 + 排序」可存为命名视图，顶部 chips 切换（Mochi 式）。**本地偏好，不同步，不复制词条**。
- 空分区默认隐藏（可开关显示）。

**B. 学习批次（队列，受限维度）**

- 只允许：主题/情景标签、来源/教材单元、频率（若有词频数据）、随机。**语义标签禁止用于新词同批**，但可用于「近义辨析」复习专项（必须带对比反馈）。
- 批次大小 5–10 词（默认 8，可配置）；初学块状：一次会话处理一个批次，批次内随机，批次间不混；复习交错：所有到期词打散按 R 升序，不按标签聚堆。
- 队列实现：`buildQueue` 增 `batch` 过滤参数（纯函数），新词按 `newOrder` 引入后切批；`similarityAvoid` 与回炉插入位保持不变。
- 若用户选了「语义标签」作学习批次：不静默禁止，给一次说明「这类词一起初学容易互相干扰，建议放到复习辨析」，并提供「仍然继续」（尊重自主，R1 §5）。
- 新词上限与复习负载联动提示（每天 20 新词稳态约 200 复习/天，Anki 经验量级，属【推断】初值）。

### 验收

- 分区计数之和＝词条数（多标签口径下按所选规则一致）；空/未标记/大小写重音边界有单测。
- 学习批次模式下队列只含该批词，批次内顺序随机且可复现（seed 注入）。
- 语义标签批次出现说明文案，不阻塞；复习辨析专项带对比反馈。
- 保存视图刷新后仍在，换设备不同步。

### 风险与人日

- 风险：大词库首次分组索引卡顿 → 增量索引或 Worker；「按组学习」变成「按组欠债」→ 批次与每日上限联动。
- 人日：**3–4**（浏览分区 2、学习批次 1–2）。

## 4. D3 学新词形态与状态表达（反馈 3）

### 现状【事实】

- `quizMode: "flip" | "choice"`（`study/types.ts:39`），**没有「展示内容 + 知道/不知道」的浏览式闪卡**。
- `StudyMode = "mixed" | "review" | "new"` 已存在（`queue.ts:54`），开始页三按钮（`StudySession.tsx:982` 附近）→「学新词」作为队列模式已有，缺的是**交互形态与引入顺序**。
- 三态派生：`new`（无 srs / state=New / reps=0）、`mastered`（state=Review 且 `scheduledDays >= 21`，**硬编码**）、其余 `learning`（`engine.ts:85-95`）。
- **状态即时性已成立**：`applyReview` 写入 srs 同时写 `status: deriveStatusFromSrs(next)`（`store.ts:774`），撤销同样重算（`:823`），同步合并也重算（`merge.ts:178`）。粗的是**语义粒度**，不是延迟。
- `medianStability` / `accuracy30` 只用于统计展示（`metrics.ts:26-27, 99-115`），未回写词条呈现。

### 证据

- Koriat & Bjork 2005：能力错觉，判断依据是加工流畅性而非未来可提取性；Nelson & Dunlosky 1991：即时 JOL 不如延迟 JOL。【强】
- Laufer & Goldstein 2004：被动识别 < 主动识别 < 被动回忆 < 主动回忆；再认成功不能推断回忆成功。【强】
- FSRS-6 首评 S0：Again≈0.21d、Hard≈1.29d、Good≈2.31d、Easy≈8.30d（默认 w0–w3）。把「眼熟」映射 Good/Easy → 首复习时 R 已低 → 失败 → post-lapse S 下调 → 用户感觉「怎么老记不住」。【事实公式 + 推断后果】
- R3 §3.3：Mochi 两阶段（New: Remembered/Forgot → Review）、墨墨四档（认识/模糊/忘记/熟知，熟知＝永久退出）、Quizlet 四档。
- 旧稿 T1/T2 与 R2 一致：练什么考什么；MC 期望猜测率 25%，正确≠独立回忆。

### 方案 A（推荐）：三步式初学，二键只路由

| 步骤 | 呈现 | 用户动作 | FSRS |
|---|---|---|---|
| 1 呈现 | 教学卡：词形+音标+释义+例句+词根/搭配（按需展开） | 「有印象 / 没印象」二键 | **不评分** |
| 2a 没印象 | 停留教学卡，可朗读、看例句 | 「我记住了」→ 进步骤 3 | 不评分 |
| 2b 有印象 | 直接再认验证（四选一，近义/同词性干扰） | 选项 | 对 → **Hard**（保守代理）；错 → **Again** + 回教学卡 |
| 3 回忆 | 隐藏释义，看词说义（自评「说对了/想很久/说不出」） | 三档自评 | 说对 → Good；想很久 → Hard；说不出 → Again |
| 4 产出（后置） | 中→英拼写/口述（T7） | 提交 | 成功且此前有回忆成功 → 才允许 Easy |

- 二键文案可选方案 B：「能说出意思 / 说不出」＋强制 2 秒思考后揭晓再勾「说对了/说错了」，以揭晓后判断为准（R2 §2.4 方案 B）。**默认用 A 的「有印象/没印象」**，因为它明确只是路由，不承诺掌握。
- 初学显式短步骤：10–30 分钟 → 1 天 → 3 天，毕业后交 FSRS（`StudySrs.learningSteps` 已有字段；ts-fsrs `enable_short_term`）。同日额外练习进 cram，不写 FSRS（与现行「连续回炉」硬规则并存，不冲突）。
- 键位：沿用现有约定，新交互必须有键位提示；二键建议 `J`（没印象）/ `K`（有印象）与翻卡四档 D/F/J/K 不冲突需实测确认，或独立模式独立键位表。
- 伪词校准（混入 5–10% 伪词估个人虚报率，Meara & Buxton 1987）：**后置可选**，需龙单独拍板是否要（会让用户遇到「不存在的词」，有信任成本）。

### 状态表达升级【建议】

- **`EntryStatus` 枚举保持不变**（`new/learning/mastered`），避免动同步与既有筛选/导出。
- 新增**派生展示层**（纯函数，不写库）：
  - 记忆强度：`R(30) = (1 + factor·30/S)^(-w20)`，`factor = 0.9^(-1/w20) - 1`，默认 w20=0.1542 → S=21d→≈87%、60d→≈94%、180d→≈98%。显示为「30 天后记得的概率」＋「下次复习：X 天后」。
  - S 桶：<1d / 1–7d / 7–30d / 30–180d / >180d（用于排序筛选，比小数稳定）。
  - 掌握层次：再认 / 回忆 / 产出（三条独立进度，来自 review_log 的 mode/kind 与结果，**本机派生**）。
- **「已掌握」文案改「稳固（当前）」**，旁边给衰减提示；升级条件：`S ≥ 21d` ＋ ≥2 次间隔 ≥7d 的成功回忆 ＋ 近 60 天无 lapse；lapse 立即降级（防抖动）。阈值属工程取值，依据强度弱–中，**需在设置里可见可解释**。
- **不做 0–100 综合掌握分**（量纲不同、不可解释、不可行动）。
- 不在「稳固」状态下隐藏复习入口（避免毕业错觉，Bahrick 1984 的 permastore 有条件）。
- 自由浏览/cram：任意分区可「练一练」，**不写 FSRS**，不计每日目标（R3 Mochi Cram / R1 §5.2）。

### 验收

- 三步式在「没印象/有印象」两条路径下评分映射正确（纯函数单测：Hard/Again/Good/Easy 边界）。
- 二键不产生 FSRS 评分；cram 不写 srs、不计 daily。
- 词条列表/详情显示 R(30) 与下次复习；lapse 后状态立即降级；升级需满足跨周条件。
- 键位提示齐全；答错必停留并示答案（硬规则不变）；隐藏词头题型揭示后才朗读。

### 风险与人日

- 风险：Hard 作再认代理语义不纯（已知取舍，单轨道下最保守）；额外点击必须可跳过不阻塞；教学卡内容缺字段时优雅回退翻卡。
- 人日：**4–6**（三步式 3–4、状态展示 1–2；不含 T7 拼写 5–8）。

## 5. D4 词库「不学习」与目标口径（反馈 4-1）

### 现状【事实】

- `computeHubMetrics(books, now)` 遍历**所有** books 累加 due/overdue/newRemaining/newPerDay/heatmap/streak（`metrics.ts:56-87`），**无任何排除开关或字段**。
- 每日限额每本书独立（`BookStudy.config.newPerDay/reviewPerDay` + `daily[ymd]`）；学习中心把各书 newPerDay 相加当总目标（`metrics.ts:58`）。
- streak＝heatmap 连续天数，**日界本地 0 点**（`metrics.ts:34-38, 89-97`），无宽恕、无开关。ROADMAP 拍板的「4 点 + 每周宽恕 + 可开关」尚未实现。
- 需同时改：`computeHubMetrics`、`computeCapacity`、`buildAdvice` 输入、`LearnHub` 的 summaries/continueTarget（`LearnHub.tsx:53-84`）。

### 证据

- R3 §3.4：Mochi **Archive deck**（不排队、保留内容/历史/标签、仍可 Cram、可逆）；RemNote **Paused**（不排队但到期时钟继续走）vs **Maintaining**（不计每日目标但仍到期）；Anki 无牌组暂停，只有 Suspend/Bury/限额 0。
- R2 §5：目标用过程指标（有效提取次数）而非时长；三档（下限/目标/挑战）；执行意图 d=0.65；已得进度；宽恕要自动、免费、只恢复连续；streak 可关闭（外部奖励可能削弱内在动机，Deci 1999）；游戏化效应有限（Sailer & Homner 2020）。
- R1 §4：desired retention 是负载主杠杆，90%→95% 约 2.5 倍复习量、→97% 约 4.5 倍；调整前必须显示预计每日量与分钟数。

### 方案【建议】：词库三态

`Wordbook.studyState?: "active" | "paused" | "archived"`（缺省 `active`，向后兼容）

| 态 | 今日计划 | 目标分母 | 到期时钟 | 可见性 | 恢复 |
|---|---|---|---|---|---|
| active | 计入 | 计入 | 正常 | 正常 | — |
| paused | **不计入** | **剔除** | **继续走** | 列表可见 + 徽标「暂停 · 到期 37」 | 逾期**分摊释放**（每日上限内逐步，不一次爆量） |
| archived | 不计入 | 剔除 | 继续走（不显示） | 默认从学习中心隐藏（可开关显示），仍可浏览与 cram | 可选「按原计划继续」或「重置到期」 |

- **不做 Maintaining 第四态**（语义复杂、收益小）；若龙只想「不计目标但仍提醒到期」，用 paused + 「到期仍提示」开关即可。
- 存储与同步：`Wordbook` 主体字段 → **LWW + `updatedAt` bump + 材料哈希**（与 2026-10-14 `Entry.suspension` 拍板同口径）；写入只经新 store action `setBookStudyState`。
- 目标口径：分母＝**active 词库的当日期望负载**（`advice.ts` 容量模型）；三档目标以「有效提取次数」计（首次尝试、带反馈的回忆/再认），已完成给明确结束状态；首次设目标引导写「如果…就…」执行意图；目标环带「已得进度」。
- streak：可开关（默认开）＋每周 1 次**自动免费宽恕**（只恢复连续，不补学习量）＋「本周 5/7」备用轨道＋日界默认 4 点、可配置 0–6，用户可见「学习日」文案；**不做付费补签**。
- 质量第二环：首次正确率 / 到期清零率（避免「打卡≠有效提取」）。
- 保持率调整前显示预计每日复习量与分钟数；考试冲刺只对高价值词库临时 0.93–0.95，不全局 ≥0.97。

### 验收

- paused/archived 词库不进 `buildQueue`、不计 hub 目标分母；徽标与到期数正确。
- 恢复 paused 后逾期按每日上限分摊（单测：注入 now，验证 N 天释放曲线）。
- 双端同步：一端改 studyState，另一端合并后一致；`updatedAt` 与材料哈希覆盖；撤销/导入备份不产生脏 history。
- streak 宽恕每周只触发一次、免费、只恢复连续；关闭后 UI 不显示 streak；4 点日界跨天行为有单测（含 0–6 配置）。

### 风险与人日

- 风险：目标分母变化需解释（「今天目标变少了」不是 bug）；本地时钟回拨/时区跳变要防负数；归档隐藏要可逆且不丢历史。
- 人日：**3–5**（词库三态 1.5–2、目标与 streak 校准 2–3）。

## 6. D5 入口收敛（反馈 4-2）

### 现状【事实】

同一意图（把词放进来）至少 **6 个一级入口 + 4 个页内面板 + 2 个间接路径**：顶导航「导入」（`TopNav.tsx:17`）、移动 Tab「导入」（`MobileTabBar.tsx:16`）、首页「导入词表」CTA + AI hero（`app/page.tsx:86, 122-130`）、词库列表「新建词库」「导入 JSON/CSV」（`books/page.tsx:62, 65`）、工作区「导入」×2 + 空态「新建词条」+ 搜索回车建词（`BookWorkspace.tsx:253, 270, 424`、`EntryList.tsx:99-101`）、`/import` 四面板、命令面板两条（`commandPalette.ts:45, 74`）、词典检索应用与 AI 管家写词。

**「导入」语义分裂**：`/books` 的导入会**新建一本书**，`/book` 的导入**写进当前书**。这是「杂乱感」主因之一（【推断】，R3 IA 对照佐证）。

### 证据

R3 §3.5：Mochi 主路径只有 New Card + Import；Quizlet Create 收敛；Anki Add / Import 分工明确。结论：**一个主入口 + 上下文入口，导入幂等**。

### 方案【建议】

1. **一个主入口「添加词」**（顶导航 + 移动 Tab 各一个，替换现「导入」），打开抽屉/页，四个 tab：单个添加、批量粘贴、文件导入（JSON/CSV/文档/图片）、AI 生成（保留 `?panel=ai` 深链）。
2. **上下文入口文案区分语义**：词库列表＝「新建词库」/「导入为新词库」；工作区＝「导入到当前词库」/「新建词条」。不再让同一个「导入」按钮在不同页做不同事。
3. 首页 CTA 收敛为一个「添加词」＋一个「继续学习」；AI hero 降为次级卡片（保留能力，不抢主路径）。
4. 命令面板动作对齐主入口命名；搜索回车建词保留（低摩擦），但给一次轻提示「已添加到当前词库」。
5. **导入幂等**：同一文件重复导入不产生重复词、不覆盖 FSRS；更新已有词时区分「只更新释义」与「重置学习记录」（后者需二次确认）。跨词库重复词用本地索引提示，不自动合并。
6. 间接路径（词典检索应用、AI 管家写词）保留，但统一走同一 store action 与同一确认 UI。

### 验收

- 一级「把词放进来」入口 ≤2（顶导航/移动 Tab 各一，同一目的地）；页内上下文入口文案语义唯一。
- 重复导入同一文件：词条数不变、srs 不变（单测 + 真机）。
- 深链 `?panel=ai`、命令面板、空态引导全部仍可达。

### 风险与人日

- 风险：改动 IA 会牵动多处文案与键位提示；老用户肌肉记忆 → 保留旧路由重定向。
- 人日：**2–3**。

**留待后续拍板（不阻塞批次一）**：① 学习目标画像（阅读/考试为主 vs 写作/口语，决定产出层是否进「稳固」定义）；② 伪词校准 5–10% 是否要；③ 手动拖动重排与 `Entry.order` 是否引入；④ paused 是否加「到期仍提示」开关；⑤ 真混淆干扰项旧稿 8 个开放问题；⑥ Word Quiz 题型 B 定稿形态（B1/B2/B3）与「不确定」档；⑦ 统计档开启门槛的用户可见承诺口径。

**以下为选项存档与理由。**

**Q1 新词闪卡的定位与评分映射**
- A（推荐）三步式：二键只路由，再认对＝Hard、错＝Again，回忆成功才 Good，产出成功才 Easy。证据最强，不污染 FSRS。
- B 纯预习：二键浏览不计分、不写 srs，只决定今天学哪些；正式学习仍走现有翻卡/选择。最轻，但「学新词」没有独立形态。
- C 三档自评毕业后写 FSRS（Mochi/墨墨式）：认识/模糊/不认识，本轮只记本地学习步，毕业时映射。体验接近竞品，但「模糊→Hard」语义需明确标注。
- D 二键直接 Again/Good：最省事，**与旧反模式 #1 冲突且证据反对**，不推荐。

**Q2 词库「不学习」的语义**
- A（推荐）三态 active/paused/archived：暂停不计目标但时钟继续、恢复分摊；归档隐藏可逆仍可浏览。
- B 只做暂停：最小改动，满足「不计目标」，但没有「彻底收起来」的能力。
- C 只做归档：不排队不计目标，但失去「暂时停几天」的轻量语义。
- D 暂停 + 仍提示到期（RemNote Maintaining 式）：不计目标但到期仍出现，适合「还想记得但不优先」。

**Q3 分组的边界**
- A（推荐）分区（浏览，任意维度）+ 学习批次（限主题/来源/频率/随机，语义标签禁新词同批）。既满足找词，又不把 UI 分类误当学习单元。
- B 分组即学习组（任意维度都可按组学，语义标签/字母序给警告）：自由度最大，但初学干扰风险由用户承担。
- C 只做浏览分区，不做按组学习：最省人日，「按组学」需求留到后续。

**Q4 第一批做哪一块**
- A（推荐）秩序与口径批（排序 + 分区 + 词库三态 + 入口收敛）：先解决每天都在碰的摩擦，不动 FSRS 语义，风险最低。
- B 初学与状态批（三步式 + R(30) + review_log）：先解决「学新词」体验与科学化，但触及评分映射，需更细验收。
- C 规则档智能批（目标规划 + 弱词队列 + 护栏）：先兑现「智能化」，但依赖日志与目标口径，宜在 A/B 之后。
- D 按依赖顺序滚动全做（A→B→C→门槛触发 D）：一次规划到位，周期最长。

**其余默认采用（除非龙否决）**：排序维度集合与持久化分域；R(30) 主指标 + 「稳固（当前）」文案 + 不做综合分；三档目标 + 自动免费宽恕 + 周达标备用轨道 + 4 点可配置；入口收敛与导入幂等；review_log 本机不同步；单轨道 FSRS（`srsByMode` 留 v2）；ML 档不做；预算只给 AI 内容；伪词校准与拖动重排后置。
