## 0. 三个 Issue 的诊断（均已定位到代码）

### #1 深色模式下学习界面颜色异常
- **根因**：`StudyCard` / `ChoiceCard` 硬编码了亮色纸感（`bg-white`、`color: "#1b1b1b"`），且卡片内部复用了
  导出卡片块（`SectionBlock`，其颜色按打印纸面设计）。暗色主题下：白卡刺眼、`Kbd`/提示与暗底对比不足。
- **方案**：学习卡引入「暗色纸面」皮肤——卡片容器改语义令牌（`bg-background-100 dark:bg-gray-100` 系），
  暗色时把 `--wv-fg/--wv-soft/--wv-line` 覆写为暗色纸面值（一行 CSS 变量即可让内部所有块联动）；
  Kbd 提示在暗底上的描边/底色同步适配。
- **成本**：0.5 天。**风险**：低（纯样式）。

### #2 网络综合词典检索过慢
- **根因**（代码实测）：`runLookup` 已是多源并发，但——
  1. 默认在线源均为**境外服务**（dictionaryapi.dev 词条 + MyMemory 机翻），国内直连慢且易超时（用户实测"特别慢"）；
  2. **零结果缓存**：同一个词每次检索都重新发出全部网络请求；
  3. 无「先到先显」的渐进渲染，被最慢的源卡住整屏。
- **方案**（按收益排序）：
  1. **L2 检索缓存**：结果按 `word + 源配置指纹` 写入 IndexedDB，TTL 30 天，命中 <10ms；命中即先渲染；
  2. **本地词库优先路径**：引导/一键导入 ECDICT（离线词典已支持），本地命中零网络；
  3. **渐进渲染**：各源 Promise 单独回调，先到先显示（可看到 localdict 秒出、在线源稍后补上）；
  4. 单源超时（默认 8s）+「快速模式」（本地 + 缓存 + 单在线源）。
- **成本**：1–1.5 天。**风险**：低。缓存需提供"刷新忽略缓存"入口。

### #3 词书内检索只能单个单词
- **现状**：`LookupPanel` 已有「批量导入单词表」（粘贴列表 → 检索 → 新建词条），但确实**没有**：
  1. 对**已有词条**的批量补全（批量编辑场景）；
  2. 书级「一键检索全部空缺」。
- **方案**：
  1. LookupPanel 新增页签「补全空缺」：扫描当前书 `senses/phonetic` 为空的词条 → 并发检索（3 路，
     复用文本导入的进度/中止模式）→ **diff 预览**（只补空缺、不覆盖）→ 一键应用；
  2. 工作区**批量编辑栏**加「批量检索」动作（对选中词条执行同一引擎）；
  3. 引擎抽为共享 `useBatchLookup`，文本导入、补全、批量编辑三处复用。
- **成本**：1–1.5 天。**风险**：低（与 #2 的缓存/并发改在同一次迭代更省）。

## 1. 跨端数据桥（手机 × 电脑）：三档低成本方案

**共同前提**：数据已是单一 JSON（`exportBackupJson` 含全部词库/词条/SRS 日志/设置/检索源）。
需要补的是「**合并引擎**」：books 按 id、entries 按 id + `updatedAt` 取新（LWW）；SRS 状态取复习时间更晚者；
每日日志按天取并集/max；设置整体 LWW。约 200 行纯函数，可单测。

| 档位 | 方案 | 成本 | 优点 | 风险/备注 |
| --- | --- | --- | --- | --- |
| A · 推荐首发 | **GitHub Gist / 私有仓库同步** | 3–4 天 | 零服务器；api.github.com **CORS 可用**（浏览器可直连）；复用现有 GitHub 用户心智 | 需用户建 PAT（轻指引）；冲突用 LWW+确认弹窗 |
| B | **WebDAV 同步**（坚果云免费 WebDAV 等） | 3–4 天 | 通用网盘；无 GitHub 也能用 | **需先 spike 坚果云 CORS**（未验证）；口令用 WebCrypto AES-GCM 端到端加密后上传 |
| C · 黑科技 | **扫码直传（WebRTC 局域网 P2P）** | 3–5 天 | 零服务器零账号；手机扫电脑二维码即完成双向合并（AirDrop 式）；「双端学习搭桥」的即时解法 | SDP 经二维码人工信令（免信令服务器）；NAT 复杂网络下回退 A/B |

**推荐组合**：A 做常态同步（启动时 + 手动），C 做「换机/两头对账」的即时桥。加密与合并引擎一次做好，
三档共用。**不建议**上 CRDT（当前场景并发写极少，LWW+日志合并足够；多端高频协作时才考虑 Yjs/Automerge）。

## 2. AI 深度集成：Agent 化 + 多模态导入 + Token 最小化

### 2.1 定位：客户端 Agent（工具在本地执行，模型只出决策）
无需后端。工具集（MVP）：`addEntries` / `updateEntries` / `addField(改 schema)` / `queryEntries`（返回紧凑摘要）/
`lookupFill`（本地检索补全，0 token）/ `generateEntries`（复用现有生成管线）/ `importFile`；删除类操作强制 UI 确认。

对话循环：**意图 → 计划 → 工具调用 → 本地执行 → 预览卡片 → 应用**。典型口令：
「加 20 个雅思写作词」「给缺音标的词补音标」「新增字段『搭配』并回填前 20 个」。

### 2.2 多模态/文件导入管道（低成本优先，AI 兜底）
| 输入 | 零成本路径 | 兜底 |
| --- | --- | --- |
| `.docx` | **mammoth.js** 纯前端提文本（1.13） | — |
| PDF（有文本层） | **pdf.js** 提取（6.x） | — |
| PDF（扫描版）/ 图片 | — | 压缩至 ≤1.5MP → **视觉模型** → 结构化 JSON |
| 文本/CSV | 现有导入器 | — |

统一出口全部汇入现有 `parseImportText → infer → 预览 → 导入`——**复用度 ~90%**。
单页词表照片 ≈ 1–3k token（几分钱）。

### 2.3 Token 最小化清单
1. 系统提示**短且稳定前缀**（DeepSeek/OpenAI 自动 KV 缓存命中，输入价约 1/10）；
2. 工具 schema 极简（短名短描述）；3. 只传摘要（字段名/数量/选中 id），不传全文；
4. 批量生成用 **NDJSON 流式**，逐行解析边收边入库、可中途停止；5. 分级路由：默认便宜模型，视觉任务独立配；
6. 已生成过的词不重复请求（本地去重）；7. `max_tokens` 上限 + 只生成用户勾选的字段。

**成本**：Agent MVP 4–6 天；多模态导入 3–4 天（docx/pdf 各半天，视觉 1–2 天）。**风险**：工具误操作 → 全部走预览确认。

## 3. 导出四主题：结构级差异化（而非换皮）

**诊断**：当前四主题共享同一骨架，仅装饰线/标签不同 → 观感趋同，"不如统一"的感受成立。
**方案 A（推荐）：主题 = 结构骨架差异**，各写一页 spec：

| 主题 | 骨架 | 排印 | 气质 |
| --- | --- | --- | --- |
| 辞书体 | 悬挂缩进义项编号、密排分隔线、单栏 | 小号衬线标签、细字距 | 牛津词典 |
| 瑞士极简 | 大留白、无标签靠缩进层级、严格网格 | 无衬线、单色灰阶 | Müller-Brockmann |
| 笔记手账 | 横线纸底、胶带式圆角标签、两栏笔记 | 行高松、可选书写线 | Hobonichi |
| 闪卡 | 每卡独立圆角边框 + 剪裁线 + 对齐标记 | 大字号词头、留白 | Anki 打印卡 |

**方案 B（收敛）**：若不想维护 4 套骨架 → 保留 3 个（辞书/瑞士/手账）+ 自定义。
另：主题选择器加**缩略图预览**（现在只有名字）。
**成本**：A 为 3–5 天；B 为 2 天。**风险**：分页引擎需对骨架差异重测（测试基建已齐，可控）。

## 4. 文案气质：从"工程说明书"到"轻盈、有温度"

**诊断**：现存文案偏理工（"文件里有什么字段，就排什么字段：缺结构就自动推断"）。
**风格指南**（建议写入 AGENTS）：短句；动词具体；用意象替代术语（"管线/归一化/映射"不出现在 UI）；
允许一句轻诗，不堆感叹号；数字要具体（"358 个词 · 10 个字段"）。
**重写示例**：

| 位置 | 现在 | 改为 |
| --- | --- | --- |
| 导入页头 | 文件里有什么字段，就排什么字段 | 把你攒下的词交给我——你有的字段一个不少，缺的结构替你补齐。 |
| 落地页副标 | 可自定义字段的单词本软件 | 一个安静的地方，存放你与单词的相遇。 |
| 学习完成 | 本轮已复习 N 个 | 这一轮，N 个词在心里落了脚。 |
| 导出页头 | 排版预览与导出 | 让它们落成纸上的样子。 |

**成本**：1 天（全站扫描 + 示例校对）。**风险**：低；建议同时给文案集中到 `src/lib/copy.ts` 便于校对。

**观察项**：鸿蒙 NEXT 无 WebView 兼容层 → 原生 ArkTS 或等待社区 `capacitor-harmony`；先列入观察不投入。
